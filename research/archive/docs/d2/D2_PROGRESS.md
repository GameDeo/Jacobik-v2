### Design decisions worth auditing
- **Extract is chunked.** Parsing and assembling one complex costs ~70 ms of the ~80 ms per complex (everything the fit needs from it is ~10 ms), so a shard (4,000 complexes) is cut into 10 chunks of 400 file blocks, one pool task each. Exactness: Q1-Q5 and QO rows concatenate in (shard, chunk) order; histograms sum; the Q6 sample is order-dependent (seeded Algorithm R per shard), so chunks write their Q6 observations uncapped and `replay_q6` runs them in order through the shard's reservoir. Test: chunked = single pass (`test_chunked_extraction_equals_the_single_pass_shard_extraction`), and the quick DB built before chunking (serial shard reservoir) has the same `entries_sha256` as the chunked one.
- **Fit is one task list on one pool.** Heavy quantities are planned and submitted first (Q5 giants, Q2, QO, Q1, Q3, Q4), keys largest first, packed into blocks of ~4 estimated seconds (cost model from the 2026-11-07 survey; blocks are transport only). Every key's random state derives from its key string; the main process runs the cheap serial parts (Q6, Q6P, NCI, Q1/Q2 pooling pass) while workers fit. QO groups are made C-contiguous before dispatch (the survey's 1e-15 serial/parallel difference).
- **Determinism**: results do not depend on `--workers` or on completion order. Entries are sorted before writing. `_meta.entries_sha256` = sha256 of entries + tables; `compare --exact` compares canonical JSON per entry. `_meta.build_run` (timestamps, timings, worker count) is the only volatile part.
- **Inputs**: `data/ref` (every file hashed in `_meta.input_hashes`), `locked_exclusions.json`, `src/fit/data/benchmark_holdout_codes.json` (copied from `refit/`, hash recorded), and the frozen 1,200-parent fit frame (Q7 table only; **not regenerable from data/ref**, hashed in `_meta.inputs.fit_frame_sha256`).
- **NPZ**: it silently dropped `ref_ll`/`ref_sd` (Q1-Q5). Fixed; the build now decodes the NPZ and compares it with the JSON entry for entry (failure -> non-zero exit).
- **`filter` stage honours the profile**: `os_sanity` and `fit_exclude_locked` are default off (production) and are **not** in the frozen D2 list, so the d2 profile leaves them off and the stage is a recorded no-op. Open question below.
- Removed: `src/fit/eta2_refit.py` (its check is the generic reproduce stage), `MAIN`/`ARCH`/`/mnt/e` constants (`typing_reextract` takes `--data-root --out-dir --frame --locked`; `tools.jgen.typing.analyse` derives them from the data root). Kept for the cleanup list (checkpoint b): `typing_reextract.py`, `fit/common/pooling.py` (duplicate of `jacobik/stats/pooling.py`), `refit/` (old driver).
